# Parametric Surrogate Modeling — worked example

A small, public, end-to-end illustration of how I would replace an
expensive process+device simulator with a fast, physics-shaped
surrogate suitable for inline **virtual metrology** and constrained
**recipe optimization** in a chip fab.

The example is a single post-implant **Rapid Thermal Anneal (RTA)** step
for a shallow boron source/drain extension. Four recipe knobs feed two
electrical KPIs:

| Inputs (recipe knobs)            | Outputs (KPIs)           |
|----------------------------------|--------------------------|
| Implant dose `[1e14, 5e15] cm⁻²` | Sheet resistance `Rs` Ω/sq |
| RTA peak temperature `[1223, 1373] K` | Junction depth `Xj` nm |
| RTA dwell time `[0.5, 30] s`     |                          |
| Chamber pressure `[1, 760] Torr` |                          |

No real wafer data, no proprietary tools, no company specifics.

## Run it

```bash
python3 -m pip install --user numpy scipy scikit-learn pandas
python3 python/generate_results.py        # ~2 s
open index.html                            # macOS — or just double-click
```

The script writes `data/samples.csv`, `data/fit_params.json`, and
`assets/data/results.json`. The HTML is fully static after that — no
server needed.

## The four-step workflow

1. **Sparse, smart sampling.** Latin Hypercube the recipe box so each
   marginal axis is uniformly covered. Log-space the knobs that span
   decades. 40 simulator calls is enough to calibrate to ~1 % on Rs.
2. **Fit equations you already trust.** The functional form is dictated
   by device physics (Arrhenius diffusion, stretched activation
   kinetics, Caughey–Thomas mobility roll-off). Only the eight
   coefficients are learned from data.
3. **Evaluate everywhere.** The fitted model is a few lines of
   arithmetic. Sweep, score, and search in microseconds per query.
4. **Optimize under real constraints.** Wrap the surrogate in SLSQP with
   the actual process limits (thermal budget, junction-depth ceiling,
   knob bounds) and pull yield back into spec.

## Three surrogates, side by side

The pipeline fits all three and the site compares them on a held-out
random grid plus a deliberate out-of-box stress test:

- **Physics-only** — sample-efficient, extrapolates gracefully,
  interpretable, but bias-limited where unmodeled effects live.
- **Black-box NN** — captures anything in-distribution, degrades quickly
  outside the training box, costs interpretability.
- **Hybrid** — physics carries the bulk trend and extrapolation, a
  small NN learns the multiplicative residual. This is the pattern most
  production virtual-metrology stacks land on.

A typical run gives Rs MAPE ≈ 0.8 % (physics) / 2.7 % (NN) / 1.9 %
(hybrid) in-distribution, and the NN error roughly **4×** when pushed
5 % beyond the training T range; physics and hybrid stay close to 1 %.

## Where AI models / agents enter

The site's "AI in the fab" tab covers this in detail:

- **Off-line:** Bayesian active-learning agents pick the next 2–5 wafers
  to run, symbolic-regression and LLM "form-proposal" agents suggest
  new compact-model terms, coefficient-sanity agents guard against
  fits that succeed numerically but lie physically.
- **On-line:** the surrogate is evaluated per wafer from FDC sensor
  traces for 100 % virtual metrology coverage, a run-to-run controller
  agent uses the Step 4 optimizer as its inner loop, drift agents
  monitor residual-NN magnitude per chamber for chamber-matching, and a
  retrieval-augmented LLM gives engineers natural-language access to
  the optimizer.
